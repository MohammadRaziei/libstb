Method

How the numbers are computed

Each corpus entry \(i\) is one image (a genre, a size and a format). For a library \(L\), \(t_i^{L}\) is the best of 7 timed runs of one operation on entry \(i\), \(s_i^{L}\) is the size in bytes of the file it wrote, and \(m_i^{L}\) is its extra peak memory. Two libraries are compared only on the entries where both ran.

  • Reference library. \(W_L=\bigl|\{\,i : t_i^{L}=\min_K t_i^{K}\,\}\bigr|\) is the number of entries on which \(L\) was fastest, and \(\mathrm{ref}=\arg\max_L W_L\) is the library that won the most. The count shows up in the per-operation summaries.
  • Headline ratio. Over the \(N\) entries both libraries ran, \(\mathbb{E}\!\left[\dfrac{t_L}{t_{\mathrm{ref}}}\right]=\dfrac{1}{N}\sum_{i=1}^{N}\dfrac{t_i^{L}}{t_i^{\mathrm{ref}}}\). It is the mean of each entry's own ratio (ratio first, then average), so a 64x64 image counts as much as a 4000x4000 one. Above 1 means \(L\) took longer than the reference. Output size and extra memory use the same formula with \(s\) and \(m\) in place of \(t\).
  • Trend charts. For an image of \(z\) pixels, let \(G_z\) be the synthetic entries of that size (photo, gradient, noise, graphics). Each library's point is \(\bar t_L(z)=\Bigl(\prod_{i\in G_z} t_i^{L}\Bigr)^{1/|G_z|}\) for time, throughput \(\dfrac{z/10^{6}}{\bar t_L(z)}\) in MP/s, and \(\bar m_L(z)=\dfrac{1}{|G_z|}\sum_{i\in G_z} m_i^{L}\) for memory. Real photographs each have an odd size of their own, so they are left out of these charts (they still count in every ratio above).
  • Reading a ratio. Averaging ratios is not symmetric: a library 10 times faster on one entry and 10 times slower on another scores \(\mathbb{E}=(0.1+10)/2=5.05\), not 1. Read it together with the win count \(W_L\).

Decoding

Reading images

Header-only reads and full decodes, from bytes and from a file, on every corpus entry: synthetic images of four shapes and real photographs, each stored as png, jpg, bmp and tga. Speed is the best of 7 runs; memory is the extra peak RSS of one isolated process per measurement.

info: read the header only, no pixels

Width, height and channel count without decoding anything. Only libstb and Pillow have a header-only call; OpenCV and imageio do not, so they are absent here.

libstb is the reference (fastest on the most corpus entries). On average (\(\mathbb{E}\!\left[\dfrac{t_{L}}{t_{\text{libstb}}}\right]\), the mean of each entry's own ratio, not a ratio of medians): Pillow 6.4× as long.

decode: encoded bytes in, pixel array out

Each file was written by Pillow, never by stb. OpenCV has no TGA decoder, so it has no TGA entries. imageio delegates to Pillow, so it is Pillow plus its own overhead.

Resizing

Resizing images

Half size and double size, with linear, cubic and box filters. Speed is the best of 7 runs; memory is the extra peak RSS of one isolated process per measurement.

resize, half size, linear (triangle)

libstb, Pillow and scikit-image prefilter when shrinking; OpenCV's INTER_LINEAR and INTER_CUBIC do not (faster, and they alias), and INTER_AREA is its antialiasing counterpart. "libstb" is Resizer(filter, srgb=False), the like-for-like pairing; "libstb (sRGB-correct)" is the library's own default, which blends in linear light like a correct resizer should, listed separately so the price of that is visible. 3-channel images only. scikit-image is skipped above 1 MP (seconds per call).

OpenCV is the reference (fastest on the most corpus entries). On average (\(\mathbb{E}\!\left[\dfrac{t_{L}}{t_{\text{OpenCV}}}\right]\), the mean of each entry's own ratio, not a ratio of medians): libstb 2.8×, libstb (sRGB-correct) 6.7×, Pillow 10.6×, scikit-image 155.3× as long.
