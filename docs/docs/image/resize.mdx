## Choosing the filter

The filter is picked by name or by enum. With no filter, libstb uses Catmull-Rom when it enlarges and
Mitchell when it shrinks. Names are case-insensitive, and `-` or a space counts as `_`.

| Filter | Names |
| --- | --- |
| default | `auto`, `default` |
| nearest | `nearest`, `point` |
| linear | `linear`, `bilinear`, `triangle` |
| cubic (Catmull-Rom) | `cubic`, `bicubic`, `catmull_rom` |
| B-spline | `bspline`, `cubic_bspline` |
| Mitchell | `mitchell` |
| box | `box`, `area` |

There is no Lanczos filter. In Python an unknown name raises `ValueError` and lists the valid names.

By default libstb blends pixels in linear light. `Resizer(filter, srgb=False)` turns that off, which is the
like-for-like setting when comparing with libraries that do not do it.

## How fast is it

The reference in these two charts is OpenCV, the library that was fastest on the most pictures. On average
libstb, with either setting, takes longer than OpenCV here, and less time than Pillow and scikit-image.
The note under each chart explains why OpenCV's linear and cubic modes are not a like-for-like comparison
when shrinking.
