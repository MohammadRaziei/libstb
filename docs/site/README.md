# libstb docs site

Docusaurus. It is the front of https://mohammadraziei.github.io/libstb/ : the home page, the lessons, and the
benchmarks page. The two API references are still generated by Doxygen (C++) and Sphinx (Python) and keep their
addresses, `cpp/html/` and `python/html/`. The Docusaurus build is merged into `docs/out/` beside them.

```
src/pages/index.tsx            home page (src/components/home/)
src/pages/benchmarks.tsx       benchmarks page, drawn from benchmarks/outputs/benchmark.json (src/components/benchmarks/)
docs/                          the guide: one lesson page (MDX) per function, served under /docs/
snippets/<lang>/<name>.*       real programs; ctest builds and runs them
languages.json                 language tabs (first entry is the default tab)
api-map.json                   C++ name <-> Python name, resolved to reference URLs by prepare.py
scripts/prepare.py             generated inputs (stdlib only): python3 scripts/prepare.py --help
scripts/make_showcase.py       the home page's demo frames, written by libstb itself
```

What replaced what:

- The generated landing page (`docs/index.html.in`, `generate_index.py`, `CreateDocs.cmake`, `supported_langs.json` and the
  `index-*` fragments) is gone. Its text and styles live in `src/components/home/` and `src/css/home.css`.
- The standalone benchmark report (`benchmarks/outputs/index.html`, `generate_report.py`, the Jinja template) is gone.
  The benchmark suite now only writes JSON (`results/*.json` and the digest `benchmark.json`), and the page draws the same
  charts from it: log-log scatter charts with a marker and a dash per library for throughput, time and memory against
  image size, horizontal bars for install size, grouped bars for fonts. The raw JSON files are linked from the page.
- Colours are not copied: `prepare.py tokens` takes the tokens section of `docs/assets/libstb-docs.css` (the file the
  Doxygen and Sphinx pages use) into `src/generated/tokens.css`.

## Build

```
cmake -S . -B build -DSTB_BUILD_DOCS=ON -DSTB_BUILD_PYTHON=ON -DSTB_BUILD_TESTS=ON
cmake --build build --target stb_docs_doxygen     # C++ reference   -> build/docs/out/cpp/html
cmake --build build --target stb_docs_sphinx      # Python reference -> build/docs/out/python/html
cmake --build build --target stb_docs_docusaurus  # home, guide, benchmarks (merged into build/docs/out)
cmake --build build --target stb_docs             # all three
ctest --test-dir build -R docs_snippet            # snippets compile and run, languages match
```

`stb_docs_docusaurus` first runs `stb_docs_figures` (the Python snippets and the home-page demo), then `npm install`
and `npm run build`. The demo downloads one photograph (see `make_showcase.py`); if that fails, the home page leaves the
demo out and the build goes on.

Set `DOCS_URL` and `DOCS_BASE_URL` for a published build. CI derives them from the repository (`https://<owner>.github.io` and
`/<repo>/`, step "Work out the Pages address" in `cmake.yml`); the defaults are `http://localhost` and `/`. Docusaurus does
not find its own address: without them the page loads no scripts and says `baseUrl = /`. While writing: `npm install && npm start` (it runs `prepare.py all` first;
the references and figures have to have been built once for links and pictures to appear).

A new language is one entry in `languages.json`, one `snippets/<id>/` folder with a file per lesson, and (for the home
page tour) one entry in `src/components/home/content.tsx`. `prepare.py check` fails when a lesson exists in some
languages and not in all.

## Windows

The first CI run hung for hours in `docs_snippet_cpp_resize` on `windows-latest`: `stb_core` is a DLL and nothing put
`stb.dll` next to `snippet_resize.exe`. The snippet CMake now copies it on Windows and gives every snippet test a 120 s
timeout.

## Not verified

Written without running anything here, so none of this has been executed:

- `npm install`, `docusaurus build` and `tsc`. The versions in `package.json` were chosen from memory (webpack is pinned
  below the release that broke webpackbar, from other projects' reports); `chart.js` 4.5.1 and `katex` 0.16.22 are the
  versions the old standalone report used. Docusaurus' `markdown.hooks.onBrokenMarkdownLinks` follows a report about 3.9.2.
- That the home page and the benchmarks page look like the pages they replace. The CSS of the home page was carried over
  by a script that prefixes every selector with `.stb-home`; the hero's entrance animation was dropped on purpose, because
  the server-rendered text would blink. The look in dark mode, the charts' recolouring when the theme changes, and keyboard
  focus were not checked.
- The CMake changes (`stb_docs_figures`, `stb_docs_docusaurus`, `stb_docs` depending on it, the merge into `docs/out`,
  the snippet tests, `GENERATE_TAGFILE` in the Doxyfile) and the Node step and base URL in `cmake.yml`.
- That the Doxygen and Sphinx pages still find everything: Doxygen's top bar loads the logo from `assets/libstb-sq.svg`,
  which now comes from this site's `static/assets/` (`prepare.py assets`), and the "== landing ==" section was removed from
  `docs/assets/libstb-docs.css` because its header said nothing else used it.
- Whether `InjectComment` (a post-build step of `stb_docs`) is harmless on Docusaurus' minified pages: it puts a comment at
  the top of every HTML file.
- That the names in `api-map.json` exist in the Doxygen tag file and Sphinx inventory. An unresolved name is shown without
  a link and `prepare.py symbols` warns about it.
- That the snippets compile and run on every CI platform.
